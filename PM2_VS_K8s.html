Node.js Architecture Guide for Kubernetes

Ditching PM2 / Clustering for Native Cloud Scaling

1. The Core Architectural Philosophy

When running applications in a cloud-native architecture, Kubernetes acts as the overall cluster manager. Running an internal process manager like PM2 or utilizing the native Node.js cluster module inside a container creates a foundational architectural conflict.

The Golden Rule

Follow the one process per container principle. Let Kubernetes scale the pods; let Node.js focus purely on processing incoming execution cycles sequentially on a single thread.

2. Why PM2 / Clustering Fails in Kubernetes

  • The Split-Brain Conflict: PM2 catches internal worker crashes and restarts them silently. Because the master process remains alive, Kubernetes probes see a healthy container and never trigger native self-healing or structural restarts.
  • Resource Blindness: By default, Node.js clusters detect the host node's total physical cores (e.g., 64 cores) rather than your container's cgroup limit. Spawning 64 workers inside a container limited to 1 or 2 CPUs causes extreme CPU throttling and out-of-memory crashes.
  • PID 1 Signal Blocking: PM2 does not act as a proper system init daemon. When Kubernetes tries to scale down or roll out a deployment, the SIGTERM signal is rarely forwarded correctly, resulting in dirty, non-graceful process destruction.
PM2 Feature Kubernetes Replacement Mechanism
pm2 start -i max (Cluster Mode) Horizontal pod scaling via replicas: X inside the Deployment template.
Automatic Crashed Restarts Native container monitoring with a restartPolicy: Always directive.
Zero-Downtime Reloads Rolling Updates paired with active Liveness and Readiness probes.

3. Production-Ready Dockerfile

Docker is 100% required to bundle your logic, configurations, and runtime dependencies into an Open Container Initiative (OCI) compliant image structure that Kubernetes can execute.

Dockerfile
FROM node:20-alpine

WORKDIR /app

# Install application dependencies securely
COPY package*.json ./
RUN npm ci --only=production

# Bundle production application source code
COPY . .

# Drop root privileges for elevated container security
USER node

EXPOSE 3000

# Launch Node directly to ensure signals are captured cleanly on PID 1
